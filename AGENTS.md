# Sift

Photo culling app. Rust core + Tauri 2 shell + React/TypeScript UI. Targets macOS, Windows, iOS, Android.

## Layout

- `crates/sift-core` — no UI, no Tauri. Container parsing (TIFF/JPEG/CR3/RAF), embedded previews, EXIF, AF areas (`af/`), ratings (`rating.rs`, `xmp.rs`), face/eye detection (`face.rs`, YuNet via tract), animals and their eyes (`animal.rs`, YOLOX-Tiny + RTMPose AP-10K), RAW development (`develop.rs`, rawler; `apple.rs`, ImageIO; `render.rs` picks between them), looks (`look.rs`: `.cube`, `.3dl`, HaldCLUT `.png`, Nikon `.NP3`), Nikon's own NEF renderer (`nikon.rs`), histogram (`histogram.rs`), frames (`frame.rs`), copy/rename/find-RAW (`export.rs`), bursts and pixel-shift series (`stack.rs`), Live Photos (`live/`: recognising a pair everywhere; writing one with `live.m`, AVFoundation, Apple only, compiled by `build.rs` with `cc`).
- `src-tauri` — commands (`commands.rs`), `sift://` image protocol (`protocol.rs`), LAN transfer server (`transfer.rs` + `transfer.html`).
- `src` — UI. `lib/store.ts` (zustand) holds all app state; `components/Pane.tsx` is the zoom/pan surface; all text lives in `lib/i18n.ts` (zh + en).

## Commands

- Core tests: `cargo test -p sift-core`. The sample-file tests need `samples/` (`bash samples/fetch.sh`, ~1.3 GB from raw.pixls.us) and compare against `exiftool` when installed; without samples they pass trivially.
- Type check: `pnpm typecheck`. Rust: `cargo check -p sift`, `cargo clippy --workspace`.
- Desktop: `pnpm tauri dev` / `pnpm tauri build`.
- iOS simulator: `pnpm tauri ios build --debug --target aarch64-sim`, then `xcrun simctl install booted src-tauri/gen/apple/build/arm64-sim/Sift.app`.
- Android: set `NDK_HOME=$ANDROID_HOME/ndk/<version>` and `JAVA_HOME`, then `pnpm tauri android build --debug --apk --target aarch64`. If Gradle cannot reach Maven (TLS handshake errors) and you need a proxy, pass it for that command only: `JAVA_TOOL_OPTIONS="-Dhttps.proxyHost=<host> -Dhttps.proxyPort=<port>"`.
- Release: `node scripts/version.mjs <x.y.z>` sets the version in `package.json`, `Cargo.toml` (workspace) and `tauri.conf.json`; add the changes under that version in `CHANGELOG.md`, commit, then push a `v<x.y.z>` tag. `.github/workflows/release.yml` checks the versions match the tag, builds the macOS (universal) and Windows (x64) installers with the full release profile, generates `THIRD-PARTY-LICENSES.html` (`cargo about`, `about.toml`), and opens a draft GitHub release for review.
- CI (`ci.yml`) runs on every push and pull request: core tests and clippy on Linux, type check and web build, and a Windows installer built with a faster profile (no LTO, 16 codegen units) on a Dev Drive; download it from the run's artifacts. A macOS build runs only on demand (`workflow_dispatch`, `macos: true`).
- Inspect one file: `cargo run -p sift-core --example probe -- <file>` (`--preview <dir>`, `--rate N`, `--face`, `--animal <files>` (`ANIMAL_OUT=<dir>` saves copies with boxes and eyes drawn), `--develop <dir>` (`ORIGINAL=1` for the no-look rendering), `--frame <dir> <style>`, `--ratings`, `--looks <photo> <dir> looks...`, `--nikon <engine root> <nef> <dir> <edge> [NP3...]` (the root is an app bundle or folder with Nikon's engine, absolute path), `--camera-look <NEF or camera JPEG> <out.NP3>`, `--stacks <files>` (the bursts and pixel-shift series among them)).

## Checking the UI without a window

Where a window cannot be screenshotted (agents, CI), the UI is exercised in headless Chrome against a loopback HTTP bridge that exposes the real commands:

    cargo run -p sift --example bridge &      # http://127.0.0.1:4777
    pnpm dev &
    node scripts/shots.mjs /path/to/photos    # screenshots in /tmp/sift-shots (ONLY=desktop,phone to filter)
    LOOKS=a.cube,b.NP3 ONLY=looks node scripts/shots.mjs /path/to/photos
    LOOKS=a.NP3 SDK_LOOKS=a ONLY=sdk node scripts/shots.mjs /path/to/photos   # bridge started with SIFT_NIKON_ROOT=<engine root>
    LOOKS=a.NP3 ONLY=tools node scripts/shots.mjs /path/to/photos   # clipping warning, saved recipe, look wall, batch apply
    ONLY=select,select-phone node scripts/shots.mjs /path/to/many-photos   # selection, drag-select, sorting, scrolling; results printed
    ONLY=animals node scripts/shots.mjs /path/to/pet-and-bird-photos   # eye close-up on animals
    ONLY=trackpad,touch node scripts/shots.mjs /path/to/photos   # gesture checks, results printed

`src/dev/mock.ts` is loaded only in dev when the URL has `?bridge=`. Debug builds also honour `SIFT_OPEN=<folder>` and `SIFT_VIEW=<index>` to open a folder/photo at launch (on the simulator: `SIMCTL_CHILD_SIFT_OPEN=demo xcrun simctl launch ...`, relative to the app's Documents).

## Rules that are easy to break

- RAW files are never rewritten. `rating::write` only overwrites same-length bytes (XMP padding absorbs growth); otherwise it writes a `.xmp` sidecar. JPEG is the only format whose segments may be resized.
- AF boxes leave `sift-core` in display orientation, normalised 0..1. Full-size previews get an EXIF orientation injected at serve time (`preview::tag_orientation`), so the webview needs no rotation logic.
- Every path coming from the webview goes through `AppState::check` (must be inside a folder opened with `scan_folder`). The transfer server addresses files by index and reduces upload names to a bare file name.
- Nikon: AF positions are in the full AF frame even for DX/1:1/16:9 crops; `af/nikon.rs` maps them into the recorded crop. The Z5 II writes AFInfo2 version `0402` like the DX Z50 II, so the grid is chosen by model first.
- Progress (flags, chosen looks, position, filter) is saved per folder through `save_session` about 250 ms after every change, with an atomic write; `last-folder.json` makes the next launch reopen it. Flags and looks are keyed by file name, and every file of a RAW+JPEG pair carries them.
- Looks are rendered from the RAW when a shot has one (`protocol::look_pixels`), starting from the rendering without the in-camera look, so they never stack on a Picture Control. Lookup tables (`.cube`, `.3dl`, HaldCLUT) are applied exactly. NP3 files are tagged records (`NCP\0`, then tag/length/value, big-endian), never fixed offsets; without Nikon's SDK they are an approximation built from the slider values (`Np3::to_lut`). Looks are shown by their name alone: the UI does not tag them "Nikon", "official" or "approx." (users took the tag to mean the look itself was Nikon's); one note in Settings explains how NP3 looks are rendered.
- Nikon's NEF/NRW Image SDK (macOS and 64-bit Windows) is in official builds only. Its interface is confidential under Nikon's licence, so nothing written from its headers or documents may be in this repository: the code that calls it is `sift-nikon`, a separate program in a private repository, and this repository has only the client and the wire protocol (`crates/sift-core/src/nikon.rs`; a look's base is a name such as `flexible-color`, never an SDK id). `Engine::bundled()` finds the engine: on macOS the app bundle itself (`Contents/MacOS/sift-nikon`, Nikon's libraries in `Contents/Frameworks`, `prm.bin` in `Contents/Resources`), on Windows the `nikon` folder next to the executable; `SIFT_NIKON_ROOT` overrides it for `tauri dev`, the bridge and `probe`. The private repository's `assemble.sh` fills `vendor/nikon-runtime/` (ignored) and writes a Tauri config there; build with `pnpm tauri build --config vendor/nikon-runtime/tauri.conf.json` to bundle it (CI does this when the `NIKON_DEPLOY_KEY` secret exists). Without it everything builds and runs, and NP3 looks are approximated. With the engine, "no look" and NP3 looks on NEF files are developed by it (`Np3::recipe`).
- Every NP3 look is developed "as shot": it is written over the Picture Control the camera recorded in an in-memory copy of the NEF (`nikon::record_look`: MakerNote 0x0023, 0x005C and 0x008C hold the NP3 records at fixed sizes; the grading hues are 16-bit in the file's byte order) and the SDK develops that copy (`Rendered::recorded`). This is the only way to give the SDK a custom tone curve. Files without those values (cameras before Flexible Color) fall back to passing the settings, plus our own curve afterwards (`Np3::apply_curve`; `Meta::look_recordable` tells which case a file is). `nikon::recorded_look` is the inverse (a photo's recipe as an NP3 file, also from camera JPEGs); for the Z f recipes checked it gives back the original NP3 byte for byte. Bump `LOOK_RENDER_VERSION` in `protocol.rs` when rendering changes, or cached renders stay.
- The helper is started as `sift-nikon <root> <port> <token>`: requests and pixels travel over a loopback socket the client listens on (the SDK prints to stdout), and the helper proves itself with the token. For a recorded look the client reads the NEF once, writes the look into a copy and sends the bytes (`source`), so trying look after look reads a file (often on a network share) once and uploads only when the look changes. Screen renders are capped at 2560 px (about 1 s; full size takes 6-15 s and is only used for export). The macOS bundle needs `com.apple.security.cs.disable-library-validation` when it is not signed by Nikon's team, which is always.
- The clipping warning is a `sift://clip` PNG of what is on screen (`histogram::clipping_mask`, same thresholds as the histogram's clipping shares), laid over the photo as one more `.tier`; like the histogram it is only asked for once a look has finished rendering. The look wall loads its tiles two at a time, since each look on a NEF is a separate SDK render.
- `Pane` keeps the live view in a ref and paints once per frame; never write `view`/`fitMode` state back into that ref during render. Which full-size image has loaded is tracked by URL (`readyUrl`), not by a boolean.
- Stacks (`stack.rs`): a Nikon burst is the run of files with the same series number in the maker note (it wraps, so neighbours must also be within a minute); pixel-shift frames carry their own mark and a merged `.NEFX` sorts first. Other makers fall back to drive mode and capture-time gaps. Hints are read with the briefs and kept in `AppState.series`; `group_shots` groups the whole folder. In the UI (`visibleEntries` in `store.ts`) a folded stack is one grid cell whose id is its first frame; grid actions on it cover every frame (`framesOf`), viewer actions only the frame on screen, and filters count frames, not stacks.
- Live Photos (`live/`): the still and the movie share a content identifier (Apple maker note key 17 in the JPEG, `com.apple.quicktime.content.identifier` in the movie) and the movie has a `still-image-time` metadata track. `scan` attaches a same-named `.mov` to a photo as `Item.live` only when the identifiers match (`live::movie_of`); it is not in `Item.paths`, so ratings never touch it, and the export sheet adds it to the copy job. Stills with a movie are left out of stack grouping. Making one (`live/writer.rs` + `live.m`) is offered on macOS only (`AppInfo.live_photo`) and saves next to the cover frame; the viewer's editor previews from thumbnails and plays existing movies from a blob (`sift://…/live`). Check a pair with `PHLivePhoto.request(withResourceFileURLs:)`.
- "Original (no look)" uses ImageIO on Apple platforms (the only decoder here that reads Nikon High Efficiency NEF) and rawler elsewhere; HE/HE* files cannot be decoded on Windows/Android.
- Overlays (AF areas, guides, crop) are drawn in screen space, outside the scaled canvas. Do not move them back inside: WebKit drops sub-pixel strokes when a huge SVG is scaled down.
- Screen-size renditions are the camera's own embedded previews passed through untouched (`preview::embedded_screen`; JPEGs carry them in MPF). Only files without one are decoded and scaled.
- Network shares (SMB) reject `fsync` with ENOTSUP on macOS; always flush through `sift_core::io::sync`, which treats that as success. A plain `sync_all()` makes every rating write on a NAS fail.
- A crop only takes effect when confirmed (`setCrop` in the store, saved per file name with the session). `Pane` then shows just that part (`frame`), and export renders it (`commands::styled_pixels`). Shots with a look or crop are exported as rendered JPEGs; everything else is a byte-for-byte copy.
- Shortcuts: `Mod` means Command on Apple and Ctrl elsewhere. `resolveKeys` drops a default that collides with a saved binding; bump `KEYS_VERSION` in the store when defaults change.
- Grid selection lives in `Library.tsx`: a range runs from `anchor` and is added to what was selected before it began (`anchor.base`), so shift-clicking back shrinks it. A plain click on one of several selected photos collapses the selection only after the double-click interval, and closing the viewer keeps a multi-selection that contains the photo. On touch screens the tick is not a target (browsers snap taps to it); a long press starts selecting.
- The grid re-renders when the first visible row changes, not per scroll event, and a new cell waits `SETTLE_MS` before asking for its thumbnail, so rows flung past cost no request. `Library` subscribes to the store through `useShallow`; do not go back to `useStore()` there.
- Sorting is a setting (`sortBy`, `sortDesc`) applied in `visibleItems`, so the viewer follows the grid. Capture times and ratings come from one pass over the files (`read_briefs`); files without a capture time sort by their modification time.
- Eye close-up: people first (`face.rs`); with no face, or when the focused AF point lies outside every face, `animal.rs` finds the animal (COCO classes: bird, cat, dog, horse, sheep, cow, elephant, bear, zebra, giraffe) and the pose network its eyes. AP-10K is mammals only: on birds the eyes are used when the network is confident (it usually is on a clear head), otherwise a focused AF point on the animal, otherwise nothing. The animal models (74 MB together) load on first need. The pose export must be read with `with_ignore_value_info(true)`.
- New npm packages resolve with a 7-day minimum release age (`pnpm-workspace.yaml`); pin Rust crates the same way.
